# MyStat 0.2.4 release preparation

Prepared with substantial Claude Code assistance on 2026-11-26.

**Status: this report covers the ad-hoc candidate, which was not itself released.** The owner had the candidate running on the physical host and approved release on 2026-11-26 without reporting per-check results, so the hands-on list below is not recorded as passed. See the release report for the final artifact.

## Candidate

- Source: `2ba63eb1fdaaff48c80f44b9eae8dbc2f33075f7` on `release/0.2.4`; version 0.2.4, build 9. Later commits on the branch change only this report.
- ZIP SHA-256: `db2563dbe91661dc05b45194df678e7c1545376cdf615bb08f80003bc831bffa`.
- Executable SHA-256: `5f1fc5c6e3c20346cc1bfc6e61151c98bafbdd948012162a65b5df3685dc31be`.
- Built with Xcode 27.2 (27B52) on macOS 27.2.1 (26B131), Parallels 27.1.0.

The only shipped change from 0.2.3 is #33: the Power card header shows the battery charge level and state (`On battery`, `Plugged in` or `Charging`) with a matching battery symbol. A Mac without a battery now shows `Plugged in` with a plug symbol instead of `On battery`, and a charge level outside 0–100 stays unavailable. Sparkle is unchanged at 2.10.1.

## Automated checks

On the host, `./scripts/release.sh --adhoc` (which runs the full test suite, including the new charge-level and symbol cases) and `./scripts/test-updates-integration.sh` passed. The guests have no developer tools, so the suites did not run in them.

## Actual-app checks

Fresh clones of the clean baselines: macOS 26.6 (25G72) and macOS 27.0.1 (26A434). The clones updated Parallels Tools to 27.1.0 on first start and restarted once; the baselines were not started. In each guest the archive and executable hashes matched the candidate and the running process path was the guest's `/Applications/MyStat.app`. The panel was opened with the shipping `--show` argument and inspected through host captures. Dark and light rendering came from the app's own `--snapshot`, offscreen.

| Check | Host, macOS 27.2.1 | macOS 26.6 | macOS 27.0.1 |
| --- | --- | --- | --- |
| Power header, battery present: level, state and symbol | Pass (`36% · Charging`, `41% · Charging`) | n/a | n/a |
| Power header, no battery: `Plugged in` with plug symbol | n/a | Pass | Pass |
| Panel at normal size, live; version 0.2.4 | Running, not yet inspected | Pass | Pass |
| Dark and light snapshot rendering, whole panel | Pass | Pass | Pass |
| 800 × 600 while open: panel refits, stays under the menu bar and above the Dock | Not run | Pass | Pass |
| Returning to normal size while open: panel restores | Not run | Pass | Pass |
| Menu-bar meter with unavailable GPU as a dash | — | Pass | Pass |

On both guests the 800 × 600 mode stayed set after the helper that set it exited, so the return to normal size was a separate mode change.

The host's snapshots show CPU as a dash and `0 cores`, because the offscreen render was taken before the first CPU interval completed. The live panel on the host showed CPU normally. This is how `--snapshot` has always behaved and is unrelated to this change.

## Not evidenced before signing

- The battery states `On battery` and `Plugged in` on physical hardware with the candidate. Only `Charging` was observed on the host, and the owner saw `On battery` with the pre-release build of #33.
- Hands-on clicks in the guests: opening the panel from the meter, close button, Escape and outside-click dismissal, gear and right-click menus, pause/resume, refresh interval. Synthetic clicks need Accessibility permission in the guests, which was not granted. No code behind these changed.
- Live dark appearance in the guests. Dark rendering was checked through `--snapshot` only.
- Manual update check, launch at login, and independent sensor accuracy.
