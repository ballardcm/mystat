## Signed upgrade before publication: not completed

The 0.2.3 harness was adapted for 0.2.3 → 0.2.4 and run in the existing macOS 26.6 and 27.0.1 clones holding the exact public 0.2.3 executable, checked by hash. Each clone updated Parallels Tools to 27.1.0 and restarted during the first attempts. Afterwards, on both guests, the harness's Sparkle 2.10.1 read the localhost feed signed with the production key and downloaded the signed archive, then made no further progress for 300 seconds and was stopped. No dialog was on screen, and the guests' logs show no error after a connection to the authorization service. Both guests were left on 0.2.3. The cause was not found.

The owner chose to publish without this check. The upgrade path is instead to be verified against the production feed after this feed merges, on the owner's host and in the guests.
