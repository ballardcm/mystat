## Build and automated tests

The release was rebuilt from the merged source. Hardware mapping tests, updater selection/URL tests, explicit OS acceptance for 26 and 27 with rejection of 15/25/28, symlink and read-only app/parent tests on both accepted OS values, feed generation/defaults, and deep strict signature verification passed. CI additionally ran the existing real Sparkle integration suite on macOS 26.

The same native Sparkle fixture harness ran inside the macOS 27.0.1 (26A434) working guest. Because that guest has no Python/Command Line Tools, a host adapter generated and signed disposable fixture apps with an ephemeral test key, transferred them to a unique guest test directory, and invoked the harness as the GUI test user. A small compiled HTTP fixture server bound only to guest localhost. The initial host-served attempt encountered the guest local-network permission restriction; it was replaced with localhost transport without granting permission or weakening protections. Temporary guest apps, servers, test defaults, and ephemeral key material were cleaned up after the run.

Observed macOS 27 fixture results:

- Default-off produced zero HTTP requests; opt-in scheduled a fetch; opt-out persisted across subsequent harness launches.
- Versions at or below the installed build and beta-channel releases were excluded. Minimum OS 28 and maximum OS 26.99 excluded the guest; the intended 26.0–27.99 range accepted it.
- Defer/cancel left the original app intact. Altered feed and archive signatures and missing feed/archive downloads failed safely.
- A correctly signed update replaced fixture build 1 with build 2, relaunched it, and preserved its sampling preference of 5. Deep strict signature verification passed.

These fixtures exercise Sparkle, not the actual MyStat controller or the production signing key. The actual app checks below cover the controller and production feed.

## Final state and limits

Both working VMs were left running MyStat 0.1.3 with automatic checks off. The owner’s host app and preferences were left untouched at 0.1.2 so the owner can drive its upgrade independently. Install 0.1.3 before upgrading that host to macOS 27 to avoid the old build’s local OS gate.

This updater fix does not modify sensor code. No macOS 27 physical sensor accuracy, browser-download quarantine/Gatekeeper first-launch qualification, or 24-hour scheduled-check soak is claimed. Artifacts remain ad-hoc signed rather than Developer ID signed/notarized. Raw diagnostics and unrelated screenshots are not committed.
