# MyStat 0.2.3 release preparation

Prepared with substantial Claude Code assistance on 2026-11-05.

**Status: this report covers the ad-hoc candidate, which was not itself released.** The owner ran the candidate on the physical host and approved release on 2026-11-05, with the hands-on list below not fully evidenced. See [the release report](2026-11-05-release-0.2.3.md) for the final artifact.

## Candidate

- Source: `d983650b0eacab6120abe30edf99056ac98f01df` on `release/0.2.3`; version 0.2.3, build 8. Later commits on the branch change only this report.
- ZIP SHA-256: `90d566e6563742cdfcbd540731678baa2caa8e94f4e627ee1c74ac09ffd789a6`.
- Executable SHA-256: `79843d3b6f953e8f8328240a4389c1e0446c3f480018296a11e4caf4810e005c`.
- Built with Xcode 27.2 (27B52) on macOS 27.0.1 (26A434), Parallels 27.0.3.

The only shipped change from 0.2.2 is bundled Sparkle 2.10.0 → 2.10.1 and the version metadata. `Sources/` is unchanged since `v0.2.2`. Sparkle 2.10.1 is not a security release. Its archive hash was computed from the download and matches the digest GitHub reports for the release asset.

## Automated checks

On the host, `./scripts/release.sh --adhoc`, `./scripts/test-updates-integration.sh` and the archive checksum passed. The guests have no developer tools, so the integration suite did not run in them. The menu-bar test binary was copied to each guest and passed its 343 state combinations.

## Actual-app checks in VMs

Fresh clones of the clean baselines: macOS 26.6 (25G72) and macOS 27.0.1 (26A434). The baselines were not started. In each guest the archive and executable hashes matched the candidate, the running process path was the guest's `Applications/MyStat.app`, and the bundled framework reported Sparkle 2.10.1 and was loaded by the process. The panel was opened with the shipping `--show` argument and inspected through host captures.

| Check | macOS 26.6 | macOS 27.0.1 |
| --- | --- | --- |
| Menu-bar meter with unavailable GPU as a dash | Pass | Pass |
| Panel at normal size, light; header and footer visible; version 0.2.3 | Pass | Pass |
| 800 × 600 while open: panel refits, stays under the menu bar and above the Dock | Pass (501 pt high) | Pass (501 pt high) |
| Returning to normal size while open: panel restores | Pass | Pass, see note |
| Escape dismissal (key sent from the host) | Pass | Pass |
| Quit and reopen: one permanent-path process | Pass | Pass |
| Automatic update checks not enabled on a clean launch (no preference written) | Pass | Pass |
| Dark rendering from the app's own `--snapshot`, offscreen | Pass | Pass |
| Live dark appearance: menu-bar meter and panel, normal size | Pass | Pass |
| Live dark appearance: panel refit at 800 × 600 while open | Pass | Pass |

Note: on macOS 27 the 800 × 600 mode applied on two of three attempts and reverted when the helper that set it exited, which is when the panel restored. The attempt that never reached 800 × 600 is not counted. On macOS 26 the mode stayed set after the helper exited, so the return to normal size there was a separate mode change.

Live dark appearance was set through the guest user's `AppleInterfaceStyle` preference and a full guest restart, then confirmed in the captures, where the system and the panel were both dark. The guests were returned to light afterwards.

Cosmetic observation: under load, around 40% in the macOS 27 capture, the white digits on the per-core CPU tiles overlap the blue fill. They remain readable with slightly lower contrast. `Sources/` is unchanged since `v0.2.2`, so this is not new in this candidate, and it does not block the release.

## Hands-on checks not evidenced before signing

Synthetic clicks were refused in the guests because the helper has no Accessibility permission, and that was not granted. These were handed to the owner for both OS versions. The owner approved release without reporting per-check results, so they are not recorded as passed. Guest state at approval showed a changed refresh interval on macOS 26 only, and no manual update check or login item on either guest.

- Opening the panel by clicking the meter; close button and outside-click dismissal.
- Gear and right-click menus, pause/resume, refresh interval selection, scrolling to the last section.
- Manual update check against the production feed, including Sparkle's own update UI, which ships in the changed framework.
- Launch at login after guest logout/login.
- Physical host: the candidate ran here with live readings, but no comparison with trusted readings was recorded. VM results say nothing about sensor compatibility.
